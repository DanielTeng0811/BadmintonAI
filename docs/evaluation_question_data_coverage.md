# Evaluation Question Data Coverage

這份檢查用來區分「系統答錯」和「資料本身不足以嚴格回答」。

目前資料可直接使用的主要訊號：

- 比賽結構：`match_id`, `set`, `rally`, `rally_id`, `ball_round`
- 球員與球種：`player`, `opponent`, `type`
- 比分與得分：`CHOU Tien Chen_score`, `Kento MOMOTA_score`, `getpoint_player`, `win_reason`, `lose_reason`
- 球與場地：`hit_area`, `hit_x`, `hit_y`, `landing_area`, `landing_x`, `landing_y`
- 站位與移動：`player_location_area`, `opponent_location_area`, `player_move_x/y`, `opponent_move_x/y`
- 技術細節：`aroundhead`, `backhand`, `hit_height`, `landing_height`

資料中沒有可靠或直接的訊號：

- 對手類型、對手能力、弱側、腳傷、體力下降、心理壓力、耐心、舒適進攻狀態
- 真正的逐拍秒數與節奏標籤。`frame_num` 可當 proxy，但不能視為正式時間標籤。
- 回球品質、偽裝、突然性、被迫/跨步救球等語意標籤。只能用欄位 proxy。

## 建議分類

### A. 可直接納入準確率

這些題目主要依賴資料中明確欄位，可以用 reference code 嚴格 judge：

`1-32`, `35-39`, `42`, `44`, `48-50`, `54-55`, `58`, `60`, `63`, `65`, `72`, `74-76`, `78`

注意：即使是 A 類，前後拍題仍必須用 `groupby(['match_id', 'set', 'rally']).shift(...)` 對齊同一個 rally。

### B. 可用 proxy，但不應當成唯一嚴格答案

這些題目可以做資料驅動 reference，但 Judge 需要接受等價 proxy，且報告要說明 proxy 口徑：

| 題號 | 原因 |
| --- | --- |
| 33-34 | 「四角拉吊」可用 hit_area 四角轉移 proxy，但資料沒有戰術標籤。 |
| 40 | 「回球品質下降」沒有品質欄位，只能用失誤、對手得分、落點等 proxy。 |
| 41 | 「讓對手主動攻擊」可用對手下一拍攻擊球種 proxy。 |
| 43 | 「被對手四角拉吊」可用對手 hit_area 四角轉移 proxy。 |
| 45 | 「激進/保守」需用球種分類 proxy。 |
| 46 | 長短回合可直接算，但「較常失誤」需要樣本數與失誤率口徑。 |
| 51 | 「領先轉膠著」可用比分差 proxy。 |
| 52 | 「回球質量降低」只能用落點過中/過淺 proxy。 |
| 53 | 「後場高遠球」可用 `type == 長球` 且落到後場 proxy。 |
| 56-57 | 連續得分可算；體力/後段狀態只能 proxy。 |
| 59 | 「逼迫對手挑球」不能證明因果，只能用周天成前一拍後對手下一拍挑球 proxy。 |
| 61-62 | 網前交換、直線/斜線可以 proxy，但需明確定義區域與方向。 |
| 64 | 「高壓球交換」需用平球/推撲球等球種 proxy。 |
| 66-71 | 被迫、被動、體力、耐心拉吊等都不是直接標籤，需 proxy。 |
| 77 | 「挑球過短」需用落點區域 proxy。 |
| 79-82 | 防守轉攻擊、壓迫、受傷、接殺布置都需要 proxy。 |
| 85-98 | 多數是戰術建議型，需要明確 proxy 口徑。 |

### C. 不建議納入嚴格準確率，除非題目改寫或明確標成 proxy

這些題目資料本身沒有足夠直接訊號，若納入總準確率會不公平：

| 題號 | 建議 | 原因 |
| --- | --- | --- |
| 47 | 改題或排除 | 問「不同對手類型」，但資料只有實際對手名稱，沒有對手類型欄位；`opponent_type` 不是對手類型。 |
| 73 | 標成資料不足或 proxy | 問節奏/每拍時間，但沒有可靠逐拍秒數；最多只能用 `frame_num` 差值 proxy。 |
| 81 | 標成 proxy 或排除 | 問對手腳受傷，資料沒有受傷/腳步受限標籤。 |
| 83 | 標成 proxy 或排除 | 問對手體力下降，資料沒有體力標籤。 |
| 84 | 標成 proxy 或排除 | 問對手後場移動速度下降，資料沒有速度下降或疲勞標籤。 |
| 88 | 標成 proxy 或排除 | 問對手後場防守能力弱，資料沒有能力弱標籤。 |
| 90 | 標成 proxy 或排除 | 問周天成感覺體力下降，資料沒有主觀體力狀態。 |
| 97 | 標成 proxy 或排除 | 問長回合中腳步變慢，資料沒有腳步變慢標籤；只能用移動距離 proxy。 |
| 99 | 標成 proxy 或排除 | 問前一場剛打完體力受損，資料沒有賽程疲勞資訊。 |
| 100 | 標成 proxy 或排除 | 問對手分析過往戰術與偽裝，資料沒有 scouting 或偽裝標籤。 |

## 評測建議

1. 準確率主表只計算 A 類題目。
2. B 類題目另算「proxy 題準確率」，Judge prompt 必須允許合理等價 proxy。
3. C 類題目不要混入主準確率；可改成「資料不足辨識能力」測試，正確答案應允許模型回答資料不足。
4. 如果保留 C 類題作教練建議題，評分不應只看 code correctness，應改用「是否清楚說明資料限制 + 是否提出合理 proxy + 是否避免捏造欄位」。
