# 題庫重分組方案
## 數量來源
### 原始可直接用題目

- 原始 `A 類`：`53` 題
- 原始 `B 類` 有效題：`37` 題  
  說明：原始 B 類中的 `81, 88, 90, 97` 改歸 `C 組`
- 原始 `C 類`：`10` 題

### 補題策略

- `A 組`：原始 `53` 題 + **新增 `7` 題** = `60`
- `B 組`：原始 `37` 題 + **新增 `3` 題** = `40`
- `C 組`：保留原始 `10` 題，不補題

## 使用建議

### 若目標是量化 correctness

建議主指標只計：

- `A-1`
- `A-2`
- `B-1`
- `B-2`

也就是 `100 題主評估池`。

### 若目標是檢查系統邊界

可另外觀察 `C 組`，但建議：

- 不納入總通過率
- 只做質性分析

### 若未來要重跑評測

建議直接按照這份新清單建立：

1. `A-1` 題組
2. `A-2` 題組
3. `B-1` 題組
4. `B-2` 題組
5. `C 組` 保留，不列入 strict correctness

這樣可以更清楚地回答：

- 模型是不是只會做簡單統計
- 模型是不是卡在時序對齊
- proxy 題到底是 proxy 定義問題，還是 judge 太嚴
