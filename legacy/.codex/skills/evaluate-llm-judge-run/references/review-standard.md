# 人工複核標準

## 證據優先順序

1. 指定 run 的 `eval_notebook.ipynb`：本輪唯一的生成程式與執行結果。
2. `LLM_as_a_Judge/example_new.ipynb`：同題的可接受參考實作，可能有多個版本。
3. `LLM_as_a_Judge/評估問題_new.txt`：題意與題號。
4. `summary.txt` 與 `eval_results.csv`：token、Judge 與流程狀態的輔助證據。

## 正確的必要條件

- 分析主體正確，未混淆周天成、對手與雙方。
- 篩選條件符合題意；必要的球種、區域、場次、局次與比分情境沒有遺漏。
- `shift()`、前後拍與最後一拍限制在同一 `match_id`、`set`、`rally`，且需要時確認球員身分。
- 不將 `getpoint_player` 為空的中間拍誤當成得分或成功。
- 比例的分子與分母對應同一問題定義，不因前置篩選意外縮小分母。
- 程式產生有意義的統計或圖表，且沒有未處理的執行錯誤。

## 可接受差異

- 範例存在多種定義時，任一合理且明確說明的定義皆可接受。
- 題意沒有指定的切分門檻、球種集合、圖表類型或代理指標可自行設定。
- 開放策略題可採資料支持的探索式統計，不要求與範例逐行相同。

## 常見錯誤

- 主體顛倒。
- 用 `getpoint_player != opponent` 判定成功，將空值中間拍計為成功。
- 僅因有圖表或 LLM Judge 判定正確就接受，未檢查資料邏輯。
